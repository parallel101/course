---

众所周知，CPU 速度越来越快，而内存速度跟不上。

如果 CPU 每运算一步都要从主存取数据，相当于爱因斯坦做数学题，但是题目要跨越山海给你送来，大部分时间全浪费在运输路上了。

好在 CPU 访问内存有局域性，刚刚用过的变量，他大概率短时间内还会再用一遍。

巧妙的是，这个“刚刚用过-下一次用”的时间差，通常服从幂律分布。

[plot of 幂律分布]

大概就是：

变量a，每秒用200次。
变量b，每秒用100次。
变量c，每秒用50次。
变量d，每秒用25次。
...

幂律分布在生活中处处可见，地球上国家的人口数，宇宙中恒星的大小。

就连程序员写出的程序“变量两次访问之间的间隔”也符合幂律分布。

这不是程序员的问题，而是合理的业务逻辑天然带有层级结构，天然带着幂律，程序员只是老实的把他们翻译成了变量的访问模式而已。

因此，CPU 工程师的解法是，设置多级缓存：

1级缓存，速度100GB/s，容量100KB
2级缓存，速度50GB/s，容量200KB
3级缓存，速度25GB/s，容量400KB
主存，可能速度10GB/s，但容量128GB

幂律地设置缓存，伺候程序员变量使用情况的幂律分布。

虽然越快的存储器单价越贵，但是只要容量小，成本就不会起飞。

这和直接把整个主存全做到100GB/s相比成本低得多，让普通老百姓也买得起。

> 而且也不只是成本问题，也是因为体积问题。速度快就需要离核心近，但是主存容量大，占地太大了，离核心这么近现在的制程工艺塞不下……

---

[plot of CPU fetch chain of cache hit]

当 CPU 第一次访问变量 a 时，这一次需要等主存跨越山海把 a 送来（100～200个周期）。然后把 a 送给 CPU 用的同时，还把 a 同时放入1～3级缓存。因为他刚刚用到了 a，大概率马上还要用。

下次 CPU 访问同一个变量 a 时，先查找1级缓存，如果 a 刚好在1级缓存里，那就不用等主存送了，直接从速度最快的1级缓存读（4～6周期）。

但问题是，如果CPU同时访问a,b,c,d,...结果1级100KB全部占满了，再来个z，就需要把最不常用的一个踢掉。假设踢掉了c，因为看起来最不常用。

如果下次 CPU 访问变量 c，就会发现 c 不在1级缓存里，需要去2级缓存找（10～20周期）。

但是2级缓存也可能满，那就可能从2级缓存里踢掉，只能去3级缓存找，再找不到就只能老老实实访问主存了。

缓存里找得到，称为缓存命中。不然就是缓存没命中。

高性能程序员需要尽可能局域性好的程序，缓存命中率高。

如果每个变量只用了一下，就再也没用了，就会让缓存命中不了。理论上应该尽可能复用。

缓存的工作原理类似于哈希表。

内存是连续的地址空间，而缓存是键-值对（键是地址，值是数据）。

```cpp
struct CPU {
    Memory memory; // 读我超慢！
    unordered_map<uint64_t, int> cache; // 快

    int read_at(uint64_t address) {
        if (cache.contains(address)) { // 缓存命中
            return cache.at(address);
        }
        int value = memory.read_at(address); // 没命中，只好去主存读
        cache[address] = value; // 读到了，缓存起来，下次用
        return value;
    }
};
```
